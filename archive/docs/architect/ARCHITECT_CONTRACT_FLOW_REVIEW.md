# Architect Contract Flow Trust Review

Code-trace review originally created on 2026-03-22, updated the same day after E3 execution fixed the trade/sign-and-trade persisted-player-truth blocker at the authoritative mutation layer, updated again on 2026-03-23 after E4 brought offer-sheet finalization onto the same canonical final-snapshot persistence model, updated later on 2026-03-23 after E5 fixed authoritative `storeOfferSheet` ownership and source-player resolution, updated again on 2026-03-23 after E6 aligned SAT modal preflight with authoritative receiving-team post-trade legality, updated again on 2026-03-24 after E7 aligned offer-sheet modal preflight with authoritative mutation-layer validation via a shared preflight function, updated again on 2026-03-24 after E8 promoted the 48-hour match window to a hard blocking violation and removed the stale `rfa_offer_sheet_stub_active` warning, and updated again on 2026-03-24 after E9 unified offer-sheet initiation onto a single authoritative preflight path.

## Executive verdict

`TRUSTWORTHY`

The authoritative mutation pipeline is strong on sequencing and atomic batch persistence. E3 closed the trade/sign-and-trade persisted-player-truth blocker, E4 did the same for offer-sheet finalization, and E5 closed the remaining offer-sheet creation truth gap: `storeOfferSheet` resolves ownership from authoritative world snapshot membership, loads canonical player truth from the resolved home-team path, and fails closed when ownership or source truth is ambiguous. E6 closes the SAT modal/preflight drift: the modal uses a shared authoritative SAT preflight backed by the receiving team’s real post-trade context, fails closed when that preflight is unavailable or incomplete, and still defers final authority to apply-time mutation validation. E7 closes the offer-sheet modal/preflight drift by adding a shared authoritative offer-sheet preflight (`preflightOfferSheetMutation`) backed by the same mutation-layer validation path (`resolveStoreOfferSheetAuthority` + `validateSigning` + `computeWorldMutation`). E8 closes the two remaining validator-level inconsistencies: the 48-hour match window is now a hard blocking violation (`offer_sheet_window_expired` promoted to `violations[]`), and the stale `rfa_offer_sheet_stub_active` warning has been removed entirely from `validateSigning`. E9 closes the final Stage 1 initiation drift: the modal now builds the same canonical offer-sheet payload used for commit, `useCapValidation` stops mixing in generic `signNew` legality when `isOfferSheet === true`, `getOfferSheetPreflight` and `preflightOfferSheetMutation` normalize the canonical offer-sheet flags/status defensively, and the modal renders only the authoritative offer-sheet preflight result. For the reviewed contract flows, no confirmed trust blockers remain.

## Closed findings table

## Store Offer Sheet Read Path (E5)

Current read path before E5:

- `handleStoreOfferSheet` sent `teamCode` as the offering team plus `playerId`.
- `loadStateForMutation('storeOfferSheet')` loaded `getPlayer(worldId, offeringTeamCode, playerId)`.
- The loader then inferred `homeTeamCode` from that offering-team-path player object and only afterward loaded the home team.
- Validation and mirrored offer-sheet creation therefore depended on player truth that could be stale, mismatched, or sourced from the wrong team path.

Corrected read path after E5:

- `loadStateForMutation('storeOfferSheet')` now resolves world lineage first and scans only explicit world team snapshots in that lineage.
- Ownership precedence is strict: unique `roster` membership wins, otherwise unique `players[]` membership wins, and any disagreement or ambiguity fails closed.
- The offering team is treated only as the actor. It is never used as the player source-of-truth path.
- After ownership resolves, canonical player truth is built only from the resolved home-team snapshot player plus the first home-team override found in lineage. No base fallback is used to break ambiguity or manufacture player truth.

Is drift currently present?

Where drift is only potential:

- `handleSaveContract` is currently fallback-only in the reviewed dashboard path, but if another surface uses it as the primary save handler, it would create committed-looking local truth without authoritative persistence.
- Offer-sheet finalization is no longer an active canonical-shape drift risk after E4, authoritative offer-sheet storage is no longer a canonical source-truth drift risk after E5, and offer-sheet initiation is no longer a preflight-routing drift risk after E9.

What should be SSOT going forward:

- The mutation pipeline should remain SSOT: `validateSigning`, `preflightSignAndTradeMutation`, `validateOfferSheetResolution`, `buildPostTradeTeamsSnapshot`, `validatePostTradeSnapshotForContext`, `validateSignAndTrade`, and `validatePostStateCapLegality`.
- UI surfaces should not independently re-implement SAT apron logic or offer-sheet resolution logic. They should either call a shared preflight helper built from the authoritative stack or render authoritative preflight results directly.
