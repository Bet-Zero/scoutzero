# Bounded draft-pick evidence foundation

The September 12, 2026 owner amendment on BZE-309 and the existing completion
plan authorizes BZE-310: partial Stage C storage/read-model work plus isolated
Stage D Apron mechanisms. Stage B remains open. This does not satisfy either
stage's exit, W10, or Architect V1 completion. The all-278 requirement and the
existing first-round Apply block remain unchanged.

`draftPickEvidence.ts` and `draftPickRetained.ts` define the storage contracts.
`buildDraftPickFoundation` validates retained lineage in both directions and
produces an immutable read model. Legacy records, referenced original picks,
source-named rights, candidate correspondences, evidence assertions, opaque
programs and original retained artifacts are separate. No legacy ID creates an
economic right. No source-named right is an executable asset in this version.

All five evidence states survive verbatim: supported in stated scope, legitimate
future outcome pending, proven non-applicable, unresolved, and conflicting.
The A/B/C/D implementation overlay never overwrites these states. A field's
support, a complete alternative set, or absence of registered current questions
cannot certify a whole asset. Effective dates are separate from publication and
capture dates; missing dates remain null. Original precision and annotations
remain in the retained artifacts. A schema pass is not source qualification or
independent acceptance.

`mapDraftPickRetained` consumes already-extracted readiness, overlay and branch
detail. Its two named pool recognizers implement only the accepted clarification:
source-named comparison clauses can receive shared-pool scope notes. Inherited
ID overlap never creates causal edges. The twelve unproven projections remain
candidate identities. Unknown programs remain retained clauses and opaque
artifacts with execution disabled, even when a familiar parser shape exists.
A newly evidenced mechanism may require a schema change and a new scope decision.

The caller must retain and authenticate the exact input artifacts and review
dispositions. New evidence produces a new release identity; this module has no
world adoption, upgrade, migration, persistence or source-collection operation.
Private retained inputs and derived output stay outside the checkout. Public
tests contain synthetic claims only.

## Isolated Apron mechanisms

`draftApronMechanisms.ts` uses the pinned Canon candidate
`6cf8aaf358c158a88e630e8a7336f7e9c3febc17`, artifact SHA-256
`23fe883f6f1aec7799fc3396bef404c250fd26beefa705582a5307766ad7ff76`.
The author executed the pinned lookup for A12.3/.4/.5/.7, L08.1/.3/.7/.8 and
L09.2/.3/.4 before implementation.

- A12.4 and L08.1: compare integer cents from the independent Apron ledger at
  the team's last regular-season game start; equality does not trigger freeze.
  The 2026–27 trigger identifies the 2034 first-round pick. Pre-2024–25 triggers
  are non-applicable under this rule.
- A12.5: release occurs at the governed midnight starting the day after the
  third at-or-below regular season in the four following seasons. The calendar
  input is distinct from the team's measurement event. Three known qualifying
  observations may decide release with the fourth explicitly future.
- L08.7: two of the four following observations above the Apron establish the
  penalty component. A12.7 supplies the separate no-penalty consequence after
  a qualifying release.
- L09.4: freeze-trigger history, current frozen state, unfreeze, penalty,
  no-penalty, ownership and placement remain distinct. Missing follow-up history
  cannot turn a known original freeze into a known current restriction.

These functions require scoped qualified input sources with accepted review and
no unresolved limitations. They do not authenticate bytes or establish the 60
missing historical observations. Unqualified, missing, conflicting, unsupported,
mistimed or misidentified required inputs block the affected component. Pending
observations carry above/at-or-below alternatives and an explicit future event.

Placement always remains blocked: this assignment calculates neither lottery
order, pool allocation nor a final draft slot. Ownership is also an independent
input, never inferred from the original team. A released restriction is not a
positive first-round trading verdict. None of these modules is imported by live
Trade Machine validation/Apply, season advance or saved-world mutation.
