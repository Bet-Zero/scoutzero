# New Schema Validator Review

## What Changed in This PR
- **Debug logging uses normalized seasons and cap hits.** `tradeDebug.logSalaries` and `logSecondApron` now derive a season string from `context.yearKey` and pull salaries via `getCapHitForSeason`, ensuring salary traces align with architect contract data.【F:src/utils/architect/tradeMachine/engine/tradeDebug.js†L45-L107】
- **Matching values redirect to the new schema implementation.** `salaryUtils.computeMatchingValues` is now a thin wrapper around the new helper that reads `contract.salariesByYear`/`capHit` values, clarifying intent to rely on architect contracts.【F:src/utils/architect/tradeMachine/utils/salaryUtils.js†L1-L49】【F:src/utils/architect/tradeMachine/utils/computeMatchingValues.js†L1-L120】
- **Input validation now checks architect contracts.** Team input validation calls `getSalaryForYear` and asserts the presence of `contract.salariesByYear`/`primaryContract.salariesByYear`, rejecting payloads without new-schema salary data.【F:src/utils/architect/tradeMachine/utils/validateInput.js†L6-L140】
- **Tests pivot to the architect schema.** Validation fixtures use `contract.salariesByYear` (with `capHit` and incentives) and cover BYC, trade kicker, rookie-scale poison pill, and TPE fit through the new salary helpers.【F:tests/newSchemaValidation.test.js†L1-L163】【F:tests/fixtures/newSchemaPlayer.js†L1-L104】

## Findings and Gaps
- **Legacy contract compatibility regressed.** `getSalaryForYear` no longer falls back to `contract_clean.salaries_by_year`, so transformed legacy contracts (e.g., upload fixes that build `contract_clean`) now return $0, causing `contractFixValidation` to fail. The function should either consume `contract_clean` or the upload transform must emit `salariesByYear` in architect shape before validation.【F:src/utils/architect/tradeHelpers.js†L24-L66】【F:tests/contractFixValidation.test.js†L50-L104】
- **Second-apron cash violations never trigger.** `validateSecondApronRules` short-circuits unless `isAtOrAboveSecondApron` is set, but the context passed from `tradeValidator` omits `totalSalary`/`isAtOrAboveSecondApron`, so cash is allowed for apron teams in tests (`tradeValidator` and `tradeValidatorEdgeCases`). The validator needs an explicit apron flag or salary fed into the context before enforcement.【F:src/utils/architect/tradeMachine/rules/basicRules.js†L43-L106】【F:src/utils/architect/tradeMachine/engine/tradeValidator.js†L186-L236】【a814dc†L1-L63】
- **Dual matching pipelines remain.** `tradeValidator` still imports `computeMatchingValues` from `matchingValues.js`, while `salaryUtils` now delegates to the architect-specific helper. The two implementations differ (e.g., cap-hit prioritization, kicker handling), so validators may compute mismatched `matchIncoming/Outgoing` depending on which helper a caller reaches. Consolidating everything on the new helper (or deleting the old one) is needed for consistent new-schema behavior.【F:src/utils/architect/tradeMachine/utils/salaryUtils.js†L1-L49】【F:src/utils/architect/tradeMachine/utils/matchingValues.js†L1-L118】
- **Input validation blocks mixed rosters.** The new `validateTeamInput` rejects any player lacking `contract.salariesByYear` or a non-zero `getSalaryForYear` result. Legacy/partial players with only `contract_clean` or salary primitives will fail early even though other validators still support them. Decide whether to keep dual-schema support (and adjust the check) or fully require architect-shaped contracts end-to-end.【F:src/utils/architect/tradeMachine/utils/validateInput.js†L53-L60】【F:src/utils/architect/tradeHelpers.js†L24-L66】
