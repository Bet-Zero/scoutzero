# 2026-01-17 Cap Sheet Contract Rules Preflight

## 1) What exists today

- All Cap Sheet mutations flow through `applyWorldMutation` (READ -> COMPUTE -> VALIDATE -> PERSIST), with non-trade validation in `capLegalityValidation.js`.
- UI guardrails for sign/extend/option live in `EditContractModal` via `useCapValidation` (Salary Engine / PlayerRulesProfile), but these do not run in the mutation pipeline.
- `capRulesProfile` provides roster limits + cap lines + `salaries.getMinimumForYOS`, but min salary enforcement is not wired into signing validation.
- Extension terms and raise limits are scaffolded in `playerRulesProfile/extensionRules.js` and exposed via Salary Engine, yet pipeline validation only checks `no_contract` and hard-cap warning.
- Contract shape diverges across writers (see P0 gaps), including option flags and signing date field names.

## 4) Minimum salary readiness

- Where YOS comes from: Salary Engine `getYearsOfService` (checks `bio.experience`, `yearsOfService`, `yearsPro`, etc.) with draft-year fallback in `buildRuleContext`.
- Minimum salary source: `capRulesProfile.salaries.getMinimumForYOS` (backed by `data/minimumSalaryScales`) + Salary Engine `minimumSalaryRules`.
- Whether used today: UI-only guardrails in `useCapValidation`; pipeline does not use YOS minimums for signings. `computeTeamCapTotals` only uses `rookieMin` for incomplete roster charges.
- Gaps: No pipeline enforcement of min salary by YOS; FreeAgentPool contracts use `yearsOfService` from `freeAgents` collection (may be missing), while pipeline loads base players with `bio.experience`.
- Risks: Silent illegal contracts if UI validation is bypassed or data is inconsistent (dev override or direct mutation calls).

## 6) Execution phase plan (with acceptance criteria)

- Phase 0 (Prereq): Contract schema alignment for sign/extend/option writers.
  - Acceptance: `contract.freeAgency` consistently uses object shape; optionUsed is boolean or a single canonical string; signing date fields standardized; length metadata fields defined.
- Phase 1: Minimum salary enforcement (YOS) for signings.
  - Acceptance: `validateSigning` blocks `contract.salariesByYear[0].salary < capRulesProfile.salaries.getMinimumForYOS(yos)` for standard contracts; two-way path clearly excluded or uses a separate minimum table; mutation pipeline rejects invalid payloads.
- Phase 2: Contract years min/max for signings.
  - Acceptance: `validateSigning` enforces max years by exception/Bird rights; UI and pipeline share the same source of max years; tests cover 1-5 year limits per exception type.
- Phase 3: Extension min/max + raise limits (using available fields only).
  - Acceptance: `validateExtension` enforces extension eligibility + term limits; required fields documented and present in RuleContext (`contractEndSeasonId`, `originalContractLength`, `contractYearsRemaining`, `yearsOfServiceAtOperation`, `lastTradedDate`, `signingDate`, awards for supermax). If any required field is missing in current player objects, list the minimum schema additions before enforcement.
