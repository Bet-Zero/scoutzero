## STEP 1 — Free Agency Action Ownership and Source of Truth

| Issue ID | Related Step(s) | Severity | Description                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | Status   |
| -------- | --------------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------- |
| FA-1-1   | FA-1A           | MEDIUM   | The feature has a real central action owner in `useArchitectActions.ts`, but the primary ownership boundary across dashboard wiring (`FreeAgencySection.tsx`), pool interaction and payload staging (`FreeAgentPool.tsx`), modal dispatch (`EditContractModal.tsx`), and mutation execution is still not explicit enough. The UI-layer files are not competing owners in practice, but the feature has no structural signal that clearly distinguishes wiring/dispatch surfaces from the authoritative mutation owner.                                                                                  | RESOLVED |

| FA-1-3   | FA-1C, FA-1D    | HIGH     | Step 1 ownership durability is now closed in live code. The grouped Free Agency owner remains the public UI contract for dashboard/section/pool wiring, world-only flows are pinned fail-closed in base mode, canonical authoritative mutation routing is guarded for sign-and-trade and the full offer-sheet lifecycle, and pool modal action availability is pinned to `actionOwner.worldOnly` rather than alternate local gating.                                                                                                                                                                    | RESOLVED |

## STEP 5 — Free Agency Offer-Sheet Creation Flow

| Issue ID | Related Step(s) | Severity | Description | Status |
|----------|------------------|----------|-------------|--------|
| FA-5-1   | FA-5A            | MEDIUM   | Outgoing offer-sheet creation is world-only, but visible offering, modal launch, and Offer Sheet toggle staging are still a multi-layer initiation seam across section-level world gating, pool-level modal launch wiring, modal-visible toggle availability, and `signNew` branch selection. The path is coherent today, but no single surface explicitly owns the full world-only initiation contract, leaving visible initiation truth vulnerable to drift as any one layer evolves independently. | RESOLVED |
| FA-5-2   | FA-5B            | HIGH     | Authoritative offer-sheet preflight and authoritative store share the same signing-preparation seam, but they remain two separate evaluations of the creation path. Contract markers (`rfaOfferSheet`, `rfaOfferSheetOnly`, `rfaOfferSheetStatus`), signing mechanism truth, and action-season context are all assumed to be identical between preflight and store, but that alignment is implicit — not enforced. If the shared seam weakens, preflight can approve one offer-sheet story while store commits a different one without any structural signal of the divergence. | RESOLVED |
| FA-5-3   | FA-5C, FA-5D     | MEDIUM   | Created offer-sheet pending-state, sync, and reload truth still flows through the more generic authoritative mutation helper path rather than an explicit offer-sheet-specific post-store executor. This indirection makes it harder to trace whether pending-offer-list visibility, local dashboard sync, and reloaded world truth are faithfully reflecting stored offer-sheet results — and no focused guardrails currently protect the preflight/store/pending-state seam from silent regression as the generic helper evolves. | RESOLVED |
