## 2. Emu Startup Flow (Exact Chain)

**Entry point**: `npm run emu` → `npx tsx scripts/emu/runEmu.ts`

**Key script chain**:

```text
npm run emu
→ npx tsx scripts/emu/runEmu.ts
  → firebase emulators:start --project=<PROJECT_ID> --import=.emulator-data --export-on-exit=.emulator-data
  → wait for Firestore 127.0.0.1:8082
  → npx tsx scripts/emu/seedIfMissing.ts
     → if players_v2 missing
        → npm run emu:seed:players-v2
           → npx tsx scripts/emu/seedPlayersIfMissing.ts --collection=players_v2
              → reads firestore_staging/_artifacts/output/players_v2/*.json
```

**Emulator persistence**:
- `scripts/emu/runEmu.ts` always starts with `--import=.emulator-data` and `--export-on-exit=.emulator-data`.
- `.emulator-data` is the persistence cache. Clearing it (or reseeding) can drop `optionsByYear` unless the base writer includes it or a migration runs post-seed.

## 3. players_v2 Base Writer Discovery (Source of Truth)

The authoritative **players_v2 document shape** is generated by the staging pipeline.

**Staging writer (shape builder)**:
- `player-scrape/firestore_staging/scripts/stage_player.ts`
  - Builds `currentContractView` (currently `options[]` + `salaryByYear`, **no `optionsByYear`**).
  - Writes staged JSON to `player-scrape/firestore_staging/_artifacts/output/players_v2/*.json`.

**Batch staging**:
- `player-scrape/firestore_staging/scripts/stage_all_players.ts`

**Production push writer**:
- `player-scrape/firestore_staging/scripts/push_staged_players.ts`
  - Uses `serviceAccountKey.json`, writes to real Firestore.

**Emulator seed writer**:
- `scripts/emu/seedPlayersIfMissing.ts`
  - Reads from `firestore_staging/_artifacts/output/players_v2/*.json` (symlinked to `player-scrape/firestore_staging/_artifacts/output`).
  - Seeds `players_v2` into emulator.

**Conclusion**: `stage_player.ts` is the **long-term SSOT writer** for `optionsByYear`. Emulator seeding inherits this output.

## 4. Recommended Always-On Wiring (OptionsByYear)

### Option 1 (Best): Bake into base writer
**Hook point**:
- `player-scrape/firestore_staging/scripts/stage_player.ts`
- Function: `buildPlayersV2Payload`
- Location: where `currentContractView` is constructed (currently just `options` + `salaryByYear`).

**Why**:
- Fixes **both** emulator and production data because **all** paths read from staged JSON.

### Option 2 (Safety Net): Post-seed migration during `npm run emu`
**Hook point**:
- `scripts/emu/seedIfMissing.ts`
- After `emu:seed:players-v2` completes (and before final verification).

**Command**:
```bash
FIRESTORE_EMULATOR_HOST=127.0.0.1:8082 \
GCLOUD_PROJECT=scoutzero-bf1ae \
FIREBASE_PROJECT_ID=scoutzero-bf1ae \
node scripts/migrations/phase2y_backfill_optionsByYear.js --write
```

**Why**:
- If `.emulator-data` is cleared or old imports are used, this guarantees `optionsByYear` exists every run.

### Option 3 (Persistence only)
Not sufficient by itself. Clearing `.emulator-data` or reseeding can drop `optionsByYear`.

## 6. Demo Project Write — Root Cause + Guardrails

### Root Cause
Several scripts initialize emulator Admin SDK with **hardcoded** projectId `demo-scoutzero`. This can write to a different logical project inside the emulator (or appear as “demo project writes”).

Examples:
- `scripts/seed/phase69_seed_architect_worlds_for_tpe_migration.js`
- `scripts/migrations/phase66_migrate_tradeExceptions.js`
- `scripts/ci/run_phase80_cap_sheet_e2e_proof.js`

### Guardrail Recommendations
1. **Require projectId confirmation** for non-emulator writes in migration scripts.
2. **Disallow emulator writes** if resolved projectId is not `scoutzero-bf1ae` unless explicitly overridden.
3. **Standardize Admin SDK init** for emulator scripts using `scripts/emu/adminEmu.ts`.
4. **Log targeting info** at script start: emulator host + resolved projectId.
5. **Fix stale help text** in `scripts/migrations/phase2y_backfill_optionsByYear.js` (currently references `localhost:8080`; should be `127.0.0.1:8082`).
