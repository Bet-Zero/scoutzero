# Tiermaker/Tieramid Preflight — 2026-02-05

## GAP Findings

**GAP: No drag-and-drop support**
Status: CONFIRMED.
Repro Steps:
1. Navigate to `/tier-maker`.
2. Add any player to a tier (open drawer, add to Pool, move with arrows).
3. Attempt to drag the player tile between tiers in Tiermaker or Tieramid; there is no drag handle or drop behavior.
Code Location: `src/features/tierMaker/TierRow.jsx` (button-only move/remove controls), `src/features/tierMaker/TieramidBoard.jsx` (arrow buttons + Place).
Evidence/Notes: There are no drag event handlers or DnD libraries in `package.json`; movement is exclusively button-driven.

**GAP: Tieramid “Add Team” team-id mismatch**
Status: CONFIRMED.
Repro Steps:
1. Navigate to `/tier-maker` and toggle to Tieramid.
2. Select any team from the “Add Team...” dropdown and click “Add Team”.
3. Pool does not populate because the filter compares a slug to the player’s display team string.
Code Location: `src/features/tierMaker/TieramidBoard.jsx` → `handleAddTeamRoster`.
State Shape: `selectedTeam` from `TeamListFull` has `{ id: slug, code, teamId, teamName }`. `allPlayers` uses `bio.display.team` and `bio.display.teamId`.
Evidence/Notes: The filter is `(p.bio?.display?.team || '').toLowerCase() === selectedTeam.id`. In Tiermaker, the analogous flow uses `bio.display.teamId` vs `selectedTeam.code/teamId` in `src/features/tierMaker/TierMakerBoard.jsx` → `handleAddTeamRoster`, which is the correct mapping for team codes.

**GAP: Tieramid Pool initialization only happens once**
Status: CONFIRMED.
Repro Steps:
1. Navigate to `/tier-maker`, toggle to Tieramid, and wait for “Loading players...” to clear.
2. Pool still shows “No players” even after the player dataset loads.
Code Location: `src/features/tierMaker/TieramidBoard.jsx` → `useState(getInitialRows(processedPlayers))` with no `useEffect` to rehydrate after `allPlayers` changes.
State Shape: `rows: Record<string, Player[]>` with `Pool` populated from `processedPlayers` only on initial render.
Evidence/Notes: `processedPlayers` is derived from `allPlayers`. When `allPlayers` is initially empty (loading), `rows.Pool` is initialized empty and never refreshed.

**GAP: Tieramid has no explicit “Remove to Pool” action**
Status: CONFIRMED.
Repro Steps:
1. In Tieramid, click “Place” on a player to put them in a row.
2. Attempt to remove the player back to Pool; there is no remove control, only arrow buttons.
Code Location: `src/features/tierMaker/TieramidBoard.jsx` (row tile controls in render).
Evidence/Notes: The only actions on placed players are `movePlayer` arrows; no handler returns a placed player to `rows.Pool`.

**GAP: Tiermaker “Remove” deletes player without returning to Pool**
Status: CONFIRMED.
Repro Steps:
1. In Tiermaker, move a Pool player into any tier.
2. Click the ✕ button on that player tile.
3. The player disappears and does not return to Pool.
Code Location: `src/features/tierMaker/TierRow.jsx` (✕ button) and `src/features/tierMaker/TierMakerBoard.jsx` → `removePlayer`.
State Shape: `tiers: Record<string, Player[]>` includes `Pool` but `removePlayer` only filters `fromTier`.
Evidence/Notes: `removePlayer` only removes from `tiers[fromTier]` and does not add back to `tiers.Pool`.

**GAP: No tier/row reordering UI**
Status: CONFIRMED.
Repro Steps:
1. In Tiermaker, try to reorder tiers; only Add/Rename/Delete exist.
2. In Tieramid, only Add Row and Delete Last Row exist; no reorder controls.
Code Location: `src/features/tierMaker/TierMakerBoard.jsx` (no reorder handlers), `src/features/tierMaker/TieramidBoard.jsx` (no reorder handlers).
State Shape: `tierOrder` and `rowOrder` are only appended or filtered.
Evidence/Notes: Order is implicit or append-only; no UI or handler changes order beyond add/remove/rename.

**GAP: Tieramid fixed slot counts hide overflow players**
Status: CONFIRMED.
Repro Steps:
1. Load a tier list in Tieramid where a row contains more players than its slot count (row index + 1).
2. Only the first N players render; the rest are not visible.
Code Location: `src/features/tierMaker/TieramidBoard.jsx` render loop uses `Array.from({ length: spots })` and `const player = rows[row][j]`.
State Shape: `rows[row]` can contain more players than `spots` when loaded from Firestore.
Evidence/Notes: Rendering is capped by `spots`, so any `rows[row].length > spots` results in hidden players.

**GAP: Cross-mode compatibility undefined (Tiermaker ↔ Tieramid on same listId)**
Status: CONFIRMED.
Repro Steps:
1. Navigate to `/tier-maker/:tierListId` from `/tier-lists`; Tiermaker auto-loads the list.
2. Toggle to Tieramid; it does not auto-load the same list.
3. Manually load the same list in Tieramid; rows use tierOrder index-based capacity, which can hide overflow players.
Code Location: `src/pages/TierMakerView.jsx` (only passes `initialTierListId` to Tiermaker), `src/features/tierMaker/TieramidBoard.jsx` (no route param usage).
Evidence/Notes: Tieramid has its own `selectedTierList` state and must be loaded manually; there is no shared state or conversion between modes.

**GAP: CreateTierListModal input contrast**

**GAP: `pb-12x` invalid Tailwind class**
Status: CONFIRMED.
Repro Steps:
1. Open Tiermaker or Tieramid.
2. The container uses `pb-12x`, which Tailwind does not recognize; padding-bottom is not applied.
Code Location: `src/features/tierMaker/TierMakerBoard.jsx`, `src/features/tierMaker/TieramidBoard.jsx`.
Evidence/Notes: `pb-12x` is not a Tailwind utility in the default scale and is not defined in config.

## Cross-Mode Behavior
Observed:
1. Tiermaker auto-loads `:tierListId` via `initialTierListId`; Tieramid does not read the route.
2. Switching modes unmounts the previous board, so state is not shared across modes.
3. Loading a Tiermaker list in Tieramid applies row capacities by index, which can hide players when tiers exceed row slot counts.
Expected (from master doc intent):
1. Same listId should load consistently across modes or clearly require manual loading.
2. Player counts should not silently disappear when switching modes.
