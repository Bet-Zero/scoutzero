# Tiermaker/Tieramid v1 UX Completeness — Execution 2

**Date**: 2026-02-13
**Scope**: Tier/row reordering, share link, export path, hardening + polish

---

## What Changed

### A) Tiermaker Tier Reordering

- Added ▲/▼ reorder buttons to each tier header in `TierRow.jsx`.
- Pool is fixed last and cannot be moved.
- `moveTierUp` / `moveTierDown` handlers added to `TierMakerBoard.jsx` — they swap items in `tierOrder` while keeping Pool pinned last.
- Reorder persists via both draft mode (sessionStorage) and saved mode (Firestore) through existing `tierOrder` serialization.

### B) Tieramid Row Reordering

- Added ▲/▼ reorder buttons to each row label in `TieramidBoard.jsx`.
- Pool is fixed last and cannot be moved.
- `moveRowUp` / `moveRowDown` handlers swap items in `rowOrder`, then immediately re-run `normalizeRowsForCapacity` so capacity semantics (row 1 = 1 spot, row 2 = 2 spots, …) are enforced after every reorder. Overflow players go to Pool.
- Reorder persists via draft (sessionStorage) and saved (Firestore) through existing `rowOrder` serialization.

### C) Share Link UX

- Added a **🔗 Share** button in the mode toggle bar (`TierMakerView.jsx`), visible in both modes.
- **Saved Mode** (has `tierListId`): copies `/tier-maker/:tierListId?mode=<current>` to clipboard, shows toast "Link copied!".
- **Draft Mode** (no `tierListId`): disabled appearance + toast hint "Save your tier list first to get a share link."
- Uses `navigator.clipboard.writeText` with error handling.

### D) Export Path (v1)

- **Screenshot View** now hides ALL controls consistently in both boards:
  - Tieramid player movement buttons (↑↓←→↩) are now hidden in screenshot mode (was missing).
  - Row rename/reorder buttons hidden in screenshot mode.
  - Mode toggle bar hidden via `onScreenshotChange` callback (now wired for both TierMakerBoard and TieramidBoard).
- Added subtle hover-reveal instruction "Use your device screenshot to capture this view" in top-right corner during screenshot mode (both boards).
- **Deferred**: Export-to-image would require a new dependency (html-to-canvas or similar). Not added in v1 to avoid risk. Documented for v2.

### E) Hardening + Polish

- **Dedupe guarantee**: `addPlayerToPool` and `addPlayersToPool` in both `TierMakerBoard.jsx` and `TieramidBoard.jsx` now check ALL tiers/rows (not just Pool) before adding. Repeated adds from drawer/team/list are silently skipped.
- **CreateTierListModal** contrast fix verified; also fixed a typo (`px-04` → `px-4`) in the button class.
- **Console errors**: No new console errors introduced. Existing `console.error` calls are all in catch blocks for legitimate failure logging.

### Manual Validation Scenarios

1. **Draft Mode** (`/tier-maker` — no listId):
   - Add players → reorder tiers/rows → refresh → state preserved via sessionStorage.
   - Share button shows grayed-out state, click shows toast instruction to save first.
2. **Saved Mode** (with tier list ID):
   - Add players → reorder tiers/rows → Save → refresh → state preserved via Firestore.
   - Share button copies URL; paste in new tab loads same list.
3. **Screenshot View**:
   - All controls (mode toggle, reorder buttons, player buttons, Pool, Save, drawer) hidden in both Tiermaker and Tieramid modes.
   - Exit button appears on hover of bottom-left corner.
4. **Dedupe**:
   - Adding same team twice to Pool → no duplicates.
   - Adding same player via drawer when already in a tier → silently skipped.
