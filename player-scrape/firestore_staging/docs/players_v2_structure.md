### Denormalized Views

The root document includes three optional denormalized view fields for fast filtering and table views:

- **`currentContractView`**: Current contract information (freeAgentYear, contractType, options, birdRights, salaryByYear, etc.) - built from contracts subcollection during staging
- **`currentEvaluationView`**: Current evaluation data (roles, subRoles, shootingProfile, badges, traits, overallGrade) - updated when evaluations are saved
- **`currentSeasonStats`**: Latest season stats (PTS, REB, AST, FG%, 3PT%, FT%, eFG%, MIN, GP) - built from latest season document

These views enable fast single-query loading for table views and filtering without needing to load subcollections. The application code prioritizes these denormalized views but falls back to subcollections for backward compatibility.

## Subcollection `contracts/{contract_N}`

Each contract is stored chronologically using ordinal IDs (`contract_1`, `contract_2`, …). The payload mirrors the normalized contract JSON with an added `metadata` block.

```json

  "contractType": "ROOKIE CONTRACT",

```

## Evaluations (Placeholder)

`players_v2/{playerId}/evaluations/{doc}` is not populated by the scraper; the site writes these documents. The expected shape is defined in `src/schemas/players_v2.ts` (`EvaluationDocZ`).

## Quick Reference

- **Root fields:** `bio`, `createdAt`, `updatedAt`, `currentContractView`, `currentEvaluationView`, `currentSeasonStats` (denormalized views)
- **Subcollections:** `contracts`, `seasons`, `views/contracts`, `evaluations` (frontend-managed)
- **Ordinal IDs:** contract documents use `contract_N`; contract views refer back via `sourceContractId`.
- **Denormalized views:** Fast filtering fields on root document; updated automatically when subcollections change

For full JSON files corresponding to this example, run the staging script and inspect `player-scrape/firestore_staging/_artifacts/output/players_v2/` (git-ignored).
